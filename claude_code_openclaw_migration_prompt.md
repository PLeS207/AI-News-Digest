# Доработка AI News Digest: Coordinator на OpenClaw

Работай в текущем существующем репозитории AI News Digest: https://github.com/PLeS207/demo.

Нужно адаптировать проект к технологиям workshop Agent Systems: перенести реальное выполнение агента Editor / Coordinator на OpenClaw, сохранить Python Researcher с официальным A2A и исправить найденные ошибки. Реализуй изменения, выполни доступные проверки и обнови документацию. После краткого описания решения переходи к работе, не останавливайся на плане.

Этот промпт уточняет прежнее ТЗ и заменяет его требование о собственном Python runtime для Editor. Если в репозитории остался ai_news_digest_claude_code_prompt.md, обнови соответствующие требования или явно пометь прежнюю архитектуру Editor как заменённую. Старый промпт не должен заставлять тебя возвращать самостоятельный Python Editor в основной сценарий.

## 2. Целевая архитектура и границы изменений

Предпочтительно четыре сервиса Docker Compose:

1. app — существующий Telegram-адаптер с allowlist, клиент OpenClaw Gateway, исполнение разрешённых backend tools, SQLite, проверка результата и доставка.
2. openclaw — настоящий OpenClaw Gateway и агент Editor / Coordinator с собственным изолированным workspace и состоянием.
3. researcher — существующий Python LLM-агент и официальный A2A server.
4. dashboard — существующий Streamlit с трассами всех участников.

Поток: Telegram → app → OpenClaw Coordinator → request_research tool → официальный A2A client → Researcher → проверенный результат → OpenClaw Coordinator → submit_digest → проверка и отправка через app.

Сохрани python-telegram-bot как транспорт: native Telegram gateway OpenClaw сейчас переносить не требуется. Это позволяет сохранить контроль результата, разделение длинных сообщений и учёт доставки. В README честно укажи, что OpenClaw выполняет Coordinator, а Telegram transport и прикладная память реализованы Python-компонентом.

Сохрани RSS, A2A-контракты, SQLite-данные и полезные тесты. Основной сценарий должен работать после одной документированной команды запуска. Пользователь не должен вручную открывать OpenClaw CLI для каждого дайджеста.

## 3. OpenClaw должен действительно выполнять Coordinator

Создай агента editor с инструкциями в workspace: AGENTS.md, SOUL.md и необходимой конфигурацией роли. Через OpenClaw должны выполняться реальные обращения к модели, выбор tools и формирование содержания дайджеста. Модель и credentials задаются приватной конфигурацией приложения.

Предпочти документированный Gateway agent API. Если релиз поддерживает клиентские function tools, app может исполнять возвращённые tool calls и отправлять tool results следующим запросом согласно контракту Gateway. Небольшой plugin допустим, если он нужен для tools или observability.

Python выполняет прикладные инструменты и транспорт; он не должен скрыто запускать прежний самостоятельный LLM Editor. OpenClaw не должен быть пустым контейнером, дополнительным чатом, shell-обёрткой старого Editor или просто прокси к provider API. Его конфигурация агента, workspace и действующие права должны влиять на реальный запрос пользователя.

Сделай OpenClaw основным режимом запуска. Старый Editor можно оставить для явно обозначенных legacy-тестов, если это полезно; автоматического fallback к нему при ошибке OpenClaw быть не должно. Недоступность OpenClaw должна давать понятную ошибку и failed trace.

## 4. Tools, права и A2A

Coordinator получает только прикладные tools: get_user_settings, update_user_settings, get_digest_history, show_last_digest, request_research, submit_digest и необходимые структурированные действия для маршрутизации запроса.

Ограничь доступные native OpenClaw tools. Для этого бота не нужны произвольный shell, браузер, прямой web/RSS fetch, произвольные файлы, дополнительные messaging channels или самостоятельные subagents. Проверь фактический список инструментов в runtime и отказ при попытке вызвать запрещённый инструмент. Backend повторно проверяет allowlist, типы аргументов и допустимость операции для текущего запроса.

Researcher сохраняет собственные инструкции, вызовы LLM, RSS tool и A2A server. У него нет tools для Telegram или чтения/изменения памяти Coordinator.

Сохрани официальный a2a-sdk, Agent Card discovery, типизированные ResearchRequest / ResearchResult, task_id, проверку завершения задачи, timeout и ограниченные retry. Вызов OpenClaw-инструмента request_research должен приводить к настоящему A2A-обмену. Не заменяй этот обмен sessions_spawn или самодельным HTTP endpoint без A2A.

Привязывай backend tools к созданному приложением контексту запроса. Модель не должна самостоятельно назначать себе чужой trace_id, пользователя или ссылаться на исследование из другой задачи.

## 5. Исправь обход формирования дайджеста

Сейчас проверка A2A есть в submit_digest, однако свободный текст LLM может уйти пользователю как дайджест без исследования.

Введи /digest как однозначный вход в поток создания дайджеста. Сохрани естественные запросы, но маршрутизируй их через структурированный intent/action и проверяемое состояние запроса. Финальный свободный текст без подтверждённого действия не должен считаться успешным результатом создания дайджеста.

Для потока digest обязательны успешное request_research и валидированный submit_digest, привязанные к этому запросу. Разрешены только статьи и ссылки из текущего ResearchResult. Свободный текст модели не заменяет принятый Digest; незавершённый или ошибочный поток даёт понятную ошибку. Ответы о настройках и обычные служебные действия сохрани.

При недоступности Researcher не создавай новости или записи об успешной доставке. При пустом результате возвращай честное сообщение об отсутствии релевантных новостей.

## 6. Память, /new и повторная отправка

Сохрани существующую SQLite как прикладную persistent memory: настройки, история и доставленные URL. Не удаляй существующие volumes и не сбрасывай пользовательские данные. Если нужна миграция схемы, сделай её совместимой и документированной.

Coordinator получает сохранённые настройки через инструменты или проверенный контекст на каждом новом запросе. Наличие SQLite само по себе недостаточно: покажи, что агент использует сохранённое значение после restart и в новой беседе.

/new должен создавать действительно новый краткосрочный контекст OpenClaw с сохранением прикладной памяти. Проверь документированную семантику сессий выбранного Gateway API; не передавай старую историю в новую беседу и не дублируй transcript при tool follow-up.

Исправь повторную отправку: /last и «Покажи последний дайджест» должны использовать общий путь доставки полного сохранённого дайджеста, разделённого на корректные сообщения. Сейчас /last обрезает текст до 4096 символов, а естественный запрос пытается отправить весь текст одним сообщением.

Убери обрезание готового HTML через [:4096]. Обработай длинную отдельную статью, длинную ссылку и символы &, <, > без незакрытых тегов или повреждённых entities. Повторная отправка не создаёт новый дайджест и не меняет счётчики delivered URLs. При частичной первой доставке не отмечай неотправленные статьи как доставленные.

## 7. Наблюдаемость и доказательство участия OpenClaw

Сохрани общий trace_id для Telegram, OpenClaw Coordinator, backend tools, A2A, Researcher, памяти и доставки. Надёжно свяжи его с реальными OpenClaw run/session IDs.

Dashboard должен показывать роль и runtime каждого агента, OpenClaw run/session ID, реальные вызовы модели и инструментов, A2A task_id, память, доставку, статусы и ошибки. Используй документированные runtime events, hooks или telemetry выбранной версии. Каждый HTTP-запрос к Gateway не обязательно равен одному LLM-вызову: не подменяй одно событие другим и не выдумывай usage.

Особенно нужны доказательства: Coordinator работает внутри OpenClaw; Researcher остаётся отдельным LLM-агентом; Coordinator инициирует A2A; оба агента присутствуют в одном trace. Fake-события пригодны для offline-тестов, но не являются live-доказательством.

## 8. Запуск и документация

Изолируй OpenClaw state и workspace этого проекта от личных установок пользователя. Сохраняй состояние в отдельных volumes. Не используй и не меняй личные профили OpenClaw/Hermes на компьютере.

Gateway и backend bridge доступны только по внутренней сети Compose и требуют необходимых credentials; dashboard публикуется на localhost. Секреты передавай только нужным сервисам: Telegram-токен нужен app, Researcher его не получает. Не записывай токены и Authorization в трассы или публичные примеры.

Исправь sources.toml: либо монтируй конфиг read-only в нужные сервисы, либо документируй пересборку и пересоздание контейнеров. Простой restart сейчас не обновляет конфиг, скопированный в Docker-образ.

Обнови .env.example, Compose, health/smoke checks, README.md, DEMO.md и HOMEWORK_CHECKLIST.md. В README используй настоящий git clone URL. Добавь краткое сопоставление с workshop: что реально используется из OpenClaw, что сохранено собственным Python-кодом, почему Hermes не нужен этому MVP. Покажи команды запуска, /new, restart без потери памяти и отдельный явный reset.

## 9. Проверки и критерии готовности

Запусти существующие тесты и добавь проверки изменённого поведения:
- вызов именно настроенного OpenClaw агента и исполнение его прикладных tools;
- запрет постороннему Telegram-пользователю до обращения к runtime;
- отсутствие digest без исследования, в том числе если модель вернула только текст;
- отказ в произвольной ссылке и запрещённом tool;
- полный повтор длинного дайджеста через оба способа, корректный HTML и частичная доставка;
- использование памяти после restart и /new;
- недоступность OpenClaw и Researcher, отсутствие скрытого fallback;
- отображение обоих runtime и общего trace в dashboard.

Если Docker доступен, проверь реальный OpenClaw runtime, загрузку workspace, effective tools и обмен с app. Для offline-интеграции допустим контролируемый fake model provider, подключённый к настоящему OpenClaw; fake HTTP-сервер вместо OpenClaw проверяет только клиент и не доказывает интеграцию. Явно раздели результаты этих проверок.

При доступных credentials выполни live-сценарий: сохранить лимит 2 → получить дайджест в Telegram → проверить OpenClaw и Researcher в dashboard → restart → /new → прочитать сохранённые настройки → получить новые ссылки → повторить длинный дайджест → проверить остановку и восстановление обоих runtime.

Если credentials отсутствуют, заверши код, доступные проверки и инструкции, перечисли непроверенные live-пункты. Не проси отправлять секреты в чат и не отмечай fake-проверки как live. При блокировке конкретного интерфейса исследуй поддерживаемую альтернативу; не выдавай stub за завершённую интеграцию.

В конце представь итоговую архитектуру, изменённые файлы, подтверждения реального участия OpenClaw, выполненные проверки с результатами и оставшиеся действия перед сдачей. Изменения оставь локально для просмотра; commit/push и публикация в рамках этой задачи не требуются.
